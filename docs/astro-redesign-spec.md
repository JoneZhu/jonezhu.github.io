# 无限犯错：Astro 改版设计与验收规格

## 分工与交付
- 需求方选择 Astro + 定制设计。Codex 负责设计、审查和验收；本机 Pi agent 负责所有产品代码实现、迁移、修复与实施。
- 沿用当前仓库与 GitHub Pages 域名 https://jonezhu.github.io/，不引入其他托管平台。
- 实现后由 Codex 独立验收，Pi 修复反馈。验收通过后按 AGENTS.md 对相关文件提交并推送当前分支。
- 内容保持真实，不能捏造个人履历、项目成绩、统计数字。保留 127 篇现有 Markdown 文章和草稿原文；不擅自润色旧文。

## 设计主张
像一本持续更新的个人思想刊物：中文编辑式排版，兼具技术实践的清晰与个人随笔的温度。
使用暖白纸面 #f8f7f3、近黑 #22231f、朱红 #b64230；辅助文字 #66675f，分隔线 #dcdcd3。
深色模式使用近黑纸面和柔和浅色文字，强调色保证对比度。
不用大渐变、玻璃质感、成堆圆角卡片、无意义图标、巨幅营销口号或每文一张装饰封面。
以排版、细线、间距和有意义的文章序号建立个性。品牌“无限犯错”可配小型排版式标记，但不能新增虚构品牌历史。

## 页面与布局
### 全局
- 宽屏内容最大约 1180px，顶栏为品牌、文章、归档、关于、搜索和主题切换。
- 手机保持可见核心导航；按钮有文字或可访问标签，44px 左右可操作区域。
- 正文默认中文；html lang=zh-CN，所有普通 UI 文案中文。英文可仅用于小号辅助刊物标签。
- 使用系统中文字体，不依赖远程字体/CDN才能阅读。展示标题可用本机宋体 serif 回退，正文清晰 sans-serif。
- 明确 hover/focus-visible 状态、跳到正文链接、语义结构、reduced-motion。禁止初始动画隐藏正文。
- 页脚简洁真实，保留作者 JohnZhu / GitHub；不加不存在的社交地址。

### 首页 /
- 短而有辨识度的刊头：小号“JohnZhu 的个人博客”，大标题“无限犯错”，一句“在技术与生活中，不断尝试，持续思考。”
- 顶部短介绍控制高度，桌面第一屏看得到真实精选文章和最新文章的开始。
- 精选区可采用一篇主推荐 + 两篇窄栏推荐的非对称版式，以字号和细线区分，不堆卡片。
- 初始精选建议用《云台跟踪算法研发中的 AI 实践与思考》《无限犯错》以及一篇近期真实文章；由配置文件控制选择。
- 最近文章列表用日期、标题、简短自动摘要、分类排列，标题是视觉主角；支持查看全部文章。
- 技术与 AI、成长与思考、生活记录可作为人工整理的展示入口，但保留所有原分类/标签及其链接，不修改原文分类层级。

### 文章列表 /blog/ 与归档 /archives/
- 完整覆盖 127 篇文章，日期倒序，分页或客户端渐进显示均可，但不能漏文。
- 归档按年份展示，日期和标题对齐；保留旧 /archives/ 年/月页、分页、categories、tags 路径的兼容。
- 分类/标签页面可共用文章列表版式，保留中文标签和层级，不因 slash 编码产生断链。
- 全文搜索：明确输入标签，可检索标题与正文，大小写不敏感，中文查询正常；有无结果和清空状态；可键盘操作。

### 文章页：保留所有旧 permalink
- 标题区：分类、文章标题、原发布日期、合理计算的阅读时长。
- 中文正文约 18px，line-height 1.85–1.95，最大宽度约 720–760px；标题 34–52px 随视口调整。
- 宽屏右侧轻量目录，窄屏折叠或置于正文前；当前段落状态可简洁实现。
- 表格、代码块可以自身横向滚动，整页不得横向溢出。保留语法高亮、代码复制（有真实反馈）、图片尺寸自适应。
- 文末提供相邻文章或返回文章列表，以及原有 utterances 评论。
- 现有 utterances 使用 JoneZhu/github-page-comment、issue-term=pathname；保留路径以维持关联，主题切换需适配。
- 不把全部文章正文在主页或搜索页渲染成 HTML 大块；安全输出摘要与搜索结果，避免 HTML 注入。

### 关于与 404
- 关于页用现有真实信息，可写“记录技术实践、AI 协作，以及关于成长与生活的思考。”；保留原开源贡献链接。
- 不从 private workspace 推断或泄露任何个人信息。
- 404 有清晰返回首页/文章页入口，匹配设计。

## 写作与技术要求
- Astro 静态输出，使用当前稳定且与本机/CI兼容的版本；锁定依赖并使用 npm ci。本机可用 Node 22: /Users/hongdazhu/.nvm/versions/node/v22.23.2/bin。
- 尽量直接读取 source/_posts 与现有 frontmatter，保留 source/_drafts 和资源目录，避免大规模移动 127 篇文章。
- 集中站点配置（品牌、介绍、精选列表、导航、评论等），便于后续维护。
- 提供 npm run dev、npm run build、npm run preview，并尽可能保留 npm run server 别名。
- 提供便捷新文章命令和 README：新建文章、图片放置/引用、预览、发布、草稿如何排除、精选如何设置。
- 保存所有既有图片访问路径：source/images 及 post_asset_folder 资源；正确处理中文、空格、大小写、编码路径、Markdown 和 HTML img。
- 迁移前先以旧 Hexo 构建生成基准清单，包括文章 URL、分类、标签、归档、图片路径；将机器可读基准存入相关审计文件，避免巨大生成站点入 Git。
- 保留旧文章路径包含年月日和文件名的规则，不能根据新的 title 或自动 slug 生成不同 URL。旧根分页、档案路径提供内容兼容或静态跳转。
- 草稿不进入公开页面或搜索；现有 future=true 语义须明确保留，不可静默漏文。
- 实际日期来自 frontmatter，不使用文件修改时间代替发布日期。
- 自定义 publicDir 或静态拷贝流程，避免原 Hexo public 产物污染 Astro 的 public 目录；dist/node_modules/.astro 不入 Git。
- 删除或隔离失效 Hexo 构建配置须有说明；不修改 unrelated 文件或子模块内部。保留必要旧配置作为迁移依据即可。
- GitHub Actions 改为匹配 Astro 的受支持 Node 版本、npm ci、构建与 dist 上传；保留现有 Pages 权限与发布语义。
- canonical、description、Open Graph 基础信息、sitemap、RSS、robots 正确；不额外生成社交分享图或虚构图片。

## 验收清单
1. npm ci / npm run build 成功，类型/静态检查无真实错误。
2. 迁移基准中全部文章可到达，127 篇内容保留，source 原文没有无关改动，草稿未公开。
3. 全部旧文章链接、内部文章链接、图片路径完成自动核验；分类/标签/归档/分页兼容被检查。
4. 使用真实内容审查首页、列表、归档、关于、技术长文、图文和404。
5. 桌面约1440、手机390及小屏320不横向溢出；正文/标题/导航不重叠。
6. 验证全文搜索中文结果与空结果、分类筛选/链接、主题切换及刷新保持、目录跳转、代码复制。
7. 深色对比、键盘焦点、标题层级、图片alt、安全输出、评论路径映射合理。
8. 提供明确改动总结、实际运行检查、已知限制；不把未跑过的浏览器测试写为通过。
